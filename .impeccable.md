## Design Context

### Users

The primary README reader is an Agent user who wants to turn a goal, an existing Skill,
an authorized conversation, or an approved behavior definition into a reusable Prompt or
Skill. They should not need prior knowledge of Loop IR, compilers, schemas, or evidence
manifests to understand the product model and choose a starting route.

### Brand Personality

Clear, credible, and forward-looking. Product explanations stay approachable and readable;
capability, safety, and compatibility claims stay precise and evidence-bounded.

### Aesthetic Direction

Use a restrained product-documentation hierarchy: one memorable product model first,
friendly quick-start examples second, and progressively disclosed engineering detail after
that. Prefer a simple vertical architecture diagram over a dense implementation graph.
Treat Skill Creator Pro, Skill Polisher, and Project Verifier as references for information
rhythm and evidence-aware claims, not as templates to copy mechanically.

### Design Principles

1. Lead with the user outcome and the unified package mental model.
2. Show `Loop Package → Adjuster → Prompt or Skill` before internal compiler details.
3. Separate implemented capabilities from planned outputs and future-standard compatibility.
4. Keep usage copy friendly; keep technical and safety claims rigorous.
5. Keep Chinese and English structurally equivalent without forcing sentence-level literal translation.
